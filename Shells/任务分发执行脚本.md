这个脚本的核心逻辑是：**先通过 `scp` 将脚本文件安全传输到目标机器，紧接着通过 `ssh` 远程触发执行**。为了让你用起来更顺手，我还加入了“执行后自动清理”和“SSH免密配置检查”的功能。

### 🚀 核心脚本：`deploy_and_run.sh`

你可以将以下代码保存为 `deploy_and_run.sh`。这个脚本支持同时向多台机器分发，并带有详细的执行日志。

```bash
#!/bin/bash

# ==============================================================================
# 脚本功能：批量分发脚本到远程主机并执行
# 依赖工具：scp, ssh
# 前置条件：建议配置 SSH 免密登录，否则每次传输都需要输入密码
# ==============================================================================

# --- 配置区域 ---
# 目标主机列表 (格式: user@ip 或 user@hostname)
# 如果有多个主机，用空格隔开
TARGET_HOSTS=(
    "root@192.168.1.101"
    "root@192.168.1.102"
    # "user@server03"
)

# 远程存放脚本的临时目录 (建议设置为一个临时路径，执行完可删除)
REMOTE_TEMP_DIR="/tmp/deploy_scripts"

# --- 参数检查 ---
if [ $# -lt 1 ]; then
    echo "❌ 错误：请指定要分发的脚本路径！"
    echo "用法: $0 <本地脚本路径> [远程执行参数]"
    exit 1
fi

LOCAL_SCRIPT_PATH="$1"
shift # 移除第一个参数，剩下的作为传递给远程脚本的参数
SCRIPT_ARGS="$@"

# 检查本地脚本是否存在
if [ ! -f "$LOCAL_SCRIPT_PATH" ]; then
    echo "❌ 错误：本地脚本 '$LOCAL_SCRIPT_PATH' 不存在。"
    exit 1
fi

SCRIPT_NAME=$(basename "$LOCAL_SCRIPT_PATH")
echo "🚀 开始分发脚本: $SCRIPT_NAME"
echo "📦 目标主机数量: ${#TARGET_HOSTS[@]}"
echo "📝 传递参数: $SCRIPT_ARGS"
echo "----------------------------------------"

# --- 主循环：分发与执行 ---
for host in "${TARGET_HOSTS[@]}"; do
    echo "⏳ 正在处理主机: $host"

    # 1. 创建远程临时目录 (防止目录不存在导致 scp 失败)
    # 使用 -o ConnectTimeout 避免连接卡死
    ssh -o ConnectTimeout=5 "$host" "mkdir -p $REMOTE_TEMP_DIR" 2>/dev/null
    if [ $? -ne 0 ]; then
        echo "   ❌ [$host] 无法创建远程目录，请检查 SSH 连接或权限。"
        continue
    fi

    # 2. 分发文件 (SCP)
    # -r 用于递归复制，-p 保留文件属性（时间戳、权限）
    scp -o ConnectTimeout=5 "$LOCAL_SCRIPT_PATH" "$host:$REMOTE_TEMP_DIR/"
    if [ $? -ne 0 ]; then
        echo "   ❌ [$host] 文件传输失败 (SCP Error)!"
        continue
    fi
    echo "   ✅ [$host] 文件传输成功"

    # 3. 远程执行 (SSH)
    # 赋予执行权限并执行
    # 注意：这里假设远程脚本是 bash 脚本。如果是其他解释器请相应调整
    remote_cmd="chmod +x $REMOTE_TEMP_DIR/$SCRIPT_NAME && bash $REMOTE_TEMP_DIR/$SCRIPT_NAME $SCRIPT_ARGS"
    
    # 执行命令并捕获输出
    ssh -o ConnectTimeout=5 "$host" "$remote_cmd"
    
    if [ $? -eq 0 ]; then
        echo "   ✅ [$host] 脚本执行成功"
        
        # 4. 清理 (可选)：执行成功后删除远程临时文件
        # 如果希望保留脚本在服务器上，可以注释掉下面这行
        ssh -o ConnectTimeout=5 "$host" "rm -rf $REMOTE_TEMP_DIR"
        echo "   🧹 [$host] 已清理临时文件"
    else
        echo "   ❌ [$host] 脚本执行失败，请检查远程日志或输出。"
    fi
    
    echo "----------------------------------------"
done

echo "🏁 所有任务处理完毕。"
```

### 🛠️ 如何使用

1.  **保存脚本**：将上面的代码保存为 `deploy_and_run.sh`。
2.  **赋予权限**：在终端执行 `chmod +x deploy_and_run.sh`。
3.  **准备被分发的脚本**：假设你有一个名为 `test_app.sh` 的脚本需要分发。
4.  **运行命令**：
    ```bash
    # 基本用法
    ./deploy_and_run.sh ./test_app.sh

    # 传递参数用法 (例如传递 "start" 参数给远程脚本)
    ./deploy_and_run.sh ./test_app.sh start --mode=prod
    ```

### 💡 关键实现细节与优化建议

为了让这个脚本在生产环境中更稳定，我为你整理了以下关键点：

#### 1. 前置条件：SSH 免密登录
虽然脚本可以配合密码使用，但在批量操作时，每次输入密码会非常痛苦且无法自动化。
*   **生成密钥**（如果还没有）：`ssh-keygen -t rsa`
*   **分发公钥**：`ssh-copy-id user@target_ip`
*   参考了搜索结果中的最佳实践，配置免密登录是实现自动化运维的基石。

#### 2. 为什么使用 `bash -s` 或 先传后执？
我在脚本中采用了 **“先 `scp` 传输，后 `ssh` 执行”** 的模式。
*   **优点**：稳定。`scp` 能够确保文件完整到达，且保留文件属性。
*   **替代方案**：你也可以使用 `ssh user@host 'bash -s' < local_script.sh`。这种方式不需要在远程机器上落地文件，适合一次性执行，但调试起来不如前者直观（因为文件不在远程机器上）。

#### 3. 安全性与清理
脚本中包含了一个清理步骤（`rm -rf`）。
*   **建议**：在生产环境中，执行完部署脚本后立即删除临时文件是一个好习惯，可以防止敏感代码残留在 `/tmp` 目录下被他人查看。

#### 4. 错误处理
脚本中加入了 `ConnectTimeout=5` 参数。
*   **作用**：如果某台机器宕机或网络不通，SSH 不会卡住整个脚本进程，而是快速跳过并报错，保证其他机器能继续执行。

### 🔄 进阶：如果你需要更复杂的同步
如果你的需求从“分发脚本”变成了“同步大量数据文件”或“只同步变化的文件”，建议将脚本中的 `scp` 替换为 `rsync`。
*   **命令示例**：`rsync -avz local_file user@host:remote_path`
*   `rsync` 支持增量同步，速度更快，适合大文件分发场景。
